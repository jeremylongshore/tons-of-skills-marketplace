## Penetration-tester findings

The pack has real operator implementations, shared finding/report/HTTP libraries and tests. Preserve that substantive work. Its25 narrow skills plus one orchestrator explain the26 tracked SKILL files; do not delete useful operators to satisfy an inconsistent prose count.

- **Authorization and scope:** malformed nonempty ROE blocks/time strings and wildcard-boundary mistakes could return authorized/clean results. Display severity filtering could hide blocking findings. Conflicting scope could still write a handoff, missing amendments could be ignored, and all-IPv6 scope could be emitted. These are checker-verdict/handoff defects; no integrated real-target authorization bypass was demonstrated. Structural signatures are not cryptographic identity verification or legal authority.
- **Evidence recording:** a failed verification rewrote its baseline, allowing the next unchanged run to appear clean; display filtering hid added-file failures. Sibling-prefix paths were mistaken for contained evidence. `claude-bxtu` owns this bounded repair; it does not promise atomic snapshots, legal chain of custody or real GPG verification.
- **Report composition:** deduplication discarded a later CRITICAL duplicate; promised unified JSONL/CVSS enrichment was absent. Executive prioritization could rank a widespread HIGH above a CRITICAL, and malformed ROE data supplied governance/risk bonuses. OWASP findings distribution was described as coverage, and mapping/edition claims needed correction. A heuristic score is not a validated risk measurement.
- **Network probes:** all transport failures often became no findings/exit0; custom sensitive paths lost built-in severity. TLS/certificate parsing, wildcard depth, chain adjacency and marker-only OCSP checks could miss or misstate evidence. SPA pages generated false archive exposures; S3 multiline XML was missed. Headers and fingerprints do not prove authenticated browser data access, origin identity, exploitability or complete repository compromise.
- **HTTP-method safety:** the narrow probe sends PUT, DELETE and WebDAV write methods to the supplied target by default, without a separate write opt-in, disposable resource or cleanup contract. `claude-8n7n` requires non-mutating defaults and evidence-bound optional active probes. Status302/401 is not proof of an exposed capability. The browser TRACE-via-XHR/session-theft narrative conflicts with the [Fetch forbidden-method definition](https://fetch.spec.whatwg.org/#forbidden-method).
- **Static code scanners:** fixtures missed documented Node exec/new Function, Ruby instance_eval/quoted SQL, Java/.NET deserialization and unsafe conditional YAML forms. Ordinary random-token assignments and named DES variants were missed; several promised crypto detectors do not exist. Single-file paths walked zero files, an advertised TypeScript selector scanned nothing, and display filters changed gate results. The hardcoded-secret scanner skips.env/.env.local and rejects its documented history option; its narrow report does redact complete dummy values.
- **Dependencies and licenses:** upstream error objects and failed enumeration became clean results; advisories and dependency identity were lost or misclassified. Python manifest routing and severity assumptions exceeded the upstream contract. License-token heuristics cannot establish legal compatibility; the audit makes no legal determination. Existing dependency-checker promotion work `claude-x476` must account for overlap with the four narrow dependency operators before promotion.
- **Legacy engines:** retained compatibility code repeats complete dummy secrets in report details, prefers longerLOW details overCRITICAL, returns success with its sole backend absent, attempts pip-audit installation automatically, and uses ambient interpreter checks without a project-isolation guarantee. The web engine returned100/100LOWRISK andexit0 after an unexpected failed check. `claude-29tt` requires a consumer/value decision before repairing or coherently retiring those routes.

These observations are tied to exact original source and bounded fixtures in the companion data. They are not claims that every input fails or that an attacker exploited a deployment.

## Primary-source corrections and limits

The [pip-audit usage contract](https://github.com/pypa/pip-audit#usage) distinguishes requirements files and project paths; absence of a severity field must not become a trustworthy severity verdict. [Python SSL documentation](https://docs.python.org/3/library/ssl.html#ssl.SSLSocket.getpeercert) explains why unverified certificate metadata may be empty. [TLS1.3](https://www.rfc-editor.org/rfc/rfc8446.html#section-1.2) cipher names do not encode the key-exchange property assumed by a substring check.

[Let's Encrypt ended OCSP service on2025-08-06](https://letsencrypt.org/2025/08/06/ocsp-service-has-reached-end-of-life); revocation advice needs issuer/profile applicability. [Rand ThreadRng security documentation](https://docs.rs/rand/latest/rand/rngs/struct.ThreadRng.html) describes a cryptographic generator with fork/state/threat-model limits, contradicting the blanket “not crypto-safe” claim. This does not establish FIPS validation or suitability for a particular system. [OWASP2021 A01](https://top10.owasp.org/2021/A01_2021-Broken_Access_Control/index.html) supports the recorded CSRF mapping correction; this report does not authorize an edition migration.

Compliance-labelled plugins, legal narratives and control identifiers were inspected as source. No DoD/STIG/FIPS, SOC2, HIPAA, GDPR, PCI, ASVS or NIST compliance/authorization verdict follows from this audit. Framework-specific remedies need version and deployment verification before application; none was applied here.
