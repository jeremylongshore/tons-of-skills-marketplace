# Safety Enforcement Register

**Status:** AUTHORITATIVE — linked from `STANDARDS.md § Canonical documents` (blueprint 727
Epic 4 bead 4.1). One row per claimed safety property: the claim's public wording and location,
the **enforcing artifact** — a file (with the enforcing mechanism) / the harness runtime / MCP
server code / the literal words **PROSE ONLY** — and which harnesses it holds for. There is no
fourth answer. A claim added anywhere in the platform without a row here is drift; the register
is corrected in the same PR that changes an enforcement boundary.

- **Compiled:** 2026-08-19, from a full-surface sweep (15 MCP plugins, root governing docs, the
  marketplace site, skill/agent frontmatter posture, the scanner suite, contributor templates).
- **Legend:** ✅ enforced (artifact named) · ⚙️ HARNESS (Claude Code runtime enforces; repo
  validates syntax only) · 📝 PROSE ONLY (no enforcing artifact) · ⚠️ enforced weaker than
  worded (gap named).

## 8. Register maintenance rule

A PR that (a) adds safety language to any public surface, (b) adds/removes/weakens a gate, or
(c) changes an MCP plugin's destructive posture MUST update this register in the same PR.
`claim-verifier` (the internal governance agent) treats an unregistered safety claim as a
failing finding. The register's escalations feed the Epic 4 beads named inline (E4.3–E4.13);
items marked "corrected" were fixed textually in the E4.1 PR itself because the claim, not the
control, was wrong.
