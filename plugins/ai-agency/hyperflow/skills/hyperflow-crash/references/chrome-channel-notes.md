# Chrome channel research notes

These notes summarize 24 Chrome for Developers uploads dated September 7 through November 7, 2026. They were prepared from public watch-page descriptions and available chapters; caption text was unavailable. They do not claim that the full videos were watched. Some CSS Podcast uploads are reruns, so check current browser support before choosing an API. Use the linked official guidance for implementation decisions.

| Topic | Review cues | Source |
|---|---|---|
| Input responsiveness | Trace the blocking work, show feedback early, and slice necessary main-thread work by elapsed time. Feature-detect `scheduler.yield()` and preserve a task-based fallback. | [Long tasks video](https://www.youtube.com/watch?v=_3V3cQf_1r4), [published guide](https://developer.chrome.com/docs/modern-web-guidance/guides/performance/break-up-long-tasks) |
| Dialogs and top layer | Reuse accessible primitives. Check keyboard dismissal and focus return. Feature-detect invoker commands and anchor positioning. For top-layer motion, test `@starting-style`, discrete `display` and `overlay` transitions, and reduced motion. | [Modal transitions video](https://www.youtube.com/watch?v=WccuSkL7KOQ), [dialog guide](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/declarative-dialog-popover-control), [top-layer guide](https://developer.chrome.com/docs/modern-web-guidance/guides/ui-behaviors/animate-to-from-top-layer) |
| CSS motion and state | Treat view transitions, scroll effects, carousels, scroll-state queries, CSS functions, and swipe actions as enhancements when browser support differs. Keep content and controls usable without motion or gestures. | [Modern Web Guidance](https://developer.chrome.com/docs/modern-web-guidance/guides) |
| Forms and dates | Use address autocomplete tokens and mobile input types. Keep manual entry usable. Choose calendars and time zones explicitly; feature-detect `Temporal` and retain a supported fallback. | [Address form guide](https://developer.chrome.com/docs/modern-web-guidance/guides/forms/autofill-address-form), [Modern Web Guidance](https://developer.chrome.com/docs/modern-web-guidance/guides) |
| Interactive canvas | Treat HTML-in-Canvas as an enhancement. Preserve a usable DOM fallback; check geometry, keyboard use, text selection, and assistive-technology behavior. | [Canvas guide](https://developer.chrome.com/docs/modern-web-guidance/guides/visual-design/expose-canvas-content-to-browser-features) |
| WebMCP | Define goals and success conditions, use narrow typed inputs and actionable errors, enforce server authorization, and confirm consequential actions. Treat tool text as untrusted. Test valid, invalid, and unauthorized paths separately. | [WebMCP video](https://www.youtube.com/watch?v=NERX01dOiEY), [tool security](https://developer.chrome.com/docs/agents/security/) |
| DevTools diagnosis | Profile the real route, including client-side navigation. For suspected leaks, compare heap snapshots before and after repeated actions and after undo/exit; inspect retaining paths before labeling growth a leak. | [Memory video](https://www.youtube.com/watch?v=StAhZk_YVkE), [DevTools memory guide](https://developer.chrome.com/docs/devtools/agents/memory) |

For additional provenance, the source review included the [Chrome Developers Videos tab](https://www.youtube.com/@ChromeDevs/videos), including uploads on invoker commands, anchor positioning, declarative dialogs, autofill, and WebMCP evaluation. A description/chapter review is a lead to official guidance, not proof of a complete video or feature evaluation.
